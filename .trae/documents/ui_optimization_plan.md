# UI 优化计划

## 研究结论

通过分析代码，我发现了以下问题和优化点：

1. **状态栏适配问题**：在 `App.js` 中使用了 `SafeAreaView` 但可能没有正确处理顶部边距
2. **页面切换动画问题**：目前使用简单的不透明度动画，阴影残留可能是因为视图没有完全卸载或动画参数设置不当
3. **模型切换样式**：当前是水平滚动的 chip 样式，可以改为更现代的设计
4. **状态持久化问题**：`HomeScreen` 中的状态（模型、参数等）没有持久化，切换标签会重置

## 修改文件清单

1. `App.js` - 优化状态栏适配和页面切换动画
2. `src/screens/HomeScreen.js` - 更换模型切换样式、添加状态持久化
3. `src/context/AppContext.js` - 增加主页状态管理
4. `src/constants/models.js` - 添加新的存储键常量
5. `src/constants/theme.js` - 添加新的样式常量（可选）

## 详细修改步骤

### 1. 优化状态栏适配
- 检查 `SafeAreaView` 的使用
- 使用 `expo-status-bar` 的 `StatusBar` 组件正确设置样式
- 确保内容不会与系统状态栏重叠

### 2. 优化页面切换动画
- 优化动画配置，调整动画时长和缓动函数
- 使用更平滑的切换方式，减少阴影残留
- 可能需要优化动画容器的样式

### 3. 更换主页模型切换样式
- 将当前的水平 scroll chip 样式改为更现代的网格或分段控制器
- 优化选中状态的视觉反馈
- 保持良好的可访问性

### 4. 状态持久化
- 在 `AppContext.js` 中添加主页状态管理
- 保存用户选择的模型、模式、参数等
- 使用 `AsyncStorage` 持久化这些状态
- 在 `HomeScreen` 初始化时恢复状态

## 风险与注意事项

- **兼容性**：确保修改在 iOS 和 Android 上都能正常工作
- **性能**：状态持久化不要影响应用启动速度
- **最小改动**：遵循最小改动原则，保持现有接口不变
- **代码规范**：严格按照 `AGENTS.md` 中的规范编写代码
